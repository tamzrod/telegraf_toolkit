# Project context

Status: Phase 0/1/2 scaffolds implemented; the operational Phase 2 Registry backend (P2L-001–P2L-007) merged into `main` via PR #6 on 2026-10-21, and the Phase 2 completion workstream (P2C-001–P2C-008) merged via PR #7. Phase 3 has started only as documentation reconciliation: no mapper feature exists, and the measurement-level read path is approved (Option A1, 2026-10-26) but not implemented.

Telegraf Toolkit is a browser-based management/control plane for official Telegraf runtimes, visual configuration, a dual-database canonical mapper, reusable connection/credential registry, and independent cross-version InfluxDB historical synchronization.

**Authority:** `IDENTITY.md`. Detailed contracts remain in `docs/`. The Go backend and React SPA scaffolds exist; the Registry backend persists profile, credential-reference, audit and ciphertext-envelope metadata in SQLite (ADR-0002, `docs/METADATA_STORE.md`), stores credential values as authenticated envelopes with keys held in a separate file (ADR-0003, `docs/SECRET_STORE.md`), serves an authorized HTTP surface with role-based permissions and an administrator-only credential attachment binding (`docs/REGISTRY_API.md`), performs read-only live capability probing with pinned-peer/SSRF controls (`docs/LIVE_PROBING.md`) and is listed by the Databases UI from the live API (`docs/LIVE_UI.md`). Authentication is static file-provisioned bearer tokens; capability outcomes are projected from observations against the detected edition; a credential replacement requires a protected, read-only authorization proof and a compare-and-swap swap, revocation refuses while anything still references the credential (P2C-007), and replacement, enrollment and revocation commit through one SQLite lifecycle transaction that re-checks the active reference, approved binding and profile endpoint/scope before the envelope write, so a concurrent revocation, rebinding, profile deletion or enrollment fails the replacement closed (P2C-008); InfluxDB 1.x is unverified. Phase 3 is not implemented: the Canonical Mapper's measurement-level read path is approved under P3-001 (Option A1), because a read-only GET survey found no query-free measurement listing on the pinned editions and found that fixed GET metadata statements do work, contradicting the probe's published POST-only conclusion; implementation is P3-002.

**Boundaries:** No managed Telegraf fork, no floating versions, no direct browser privileged credentials/Docker access, no implicit deployment or historian repair, and no count-match equivalence claim. The metadata store holds credential references and ciphertext; plaintext values and keys never enter it. The browser ships live listing, read-only probing, profile create/delete and the administrator-only credential lifecycle (P2C-004–P2C-008); runtime secret delivery, usage/dependency inspection and browser master-key rotation remain unimplemented.

**Open decisions:** host-agent interface, production packaging and concrete adapters. Preserve these as unresolved. (Metadata store and secret-store custody were decided in ADR-0002/ADR-0003.) The Phase 3 measurement-level read path was decided on 2026-10-26 (Option A1: bounded GET-only fixed `SHOW` statements under a dedicated `schema.read`), approved and not implemented (`docs/decisions/phase-3-schema-discovery-gate.md` §11).
